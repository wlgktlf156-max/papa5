# 파티프로덕션디자인 아카데미(PaPA) 제5회 마친보람맺음전 — 3D 전시장 데모

온라인 3D 전시 웹사이트의 **1단계: 빈 전시장 보행 데모**입니다.
관람객은 로우폴리 인체 캐릭터를 보면서 전시장을 걸어 다니고, 작품 앞에 가까이 가면 그 작품이
빛나면서 선택할 수 있게 됩니다.

- 기간 표기: 2027. 01. 20 – 02. 28 (**예정**, 종료일은 아직 미정)
- 기술: three.js r187을 **로컬 파일로 포함** (인터넷 없이도 열립니다), 빌드 도구 없음
- 작품 목록은 `works.json` 한 파일에, 사진은 `works/` 폴더에 있습니다 — **코드를 고치지 않고 작품을 추가**할 수 있습니다.
- 이 폴더를 그대로 정적 호스팅에 올리면 됩니다(배포는 아직 하지 않았습니다)

---

## 1. 로컬에서 여는 방법

이 폴더에서 정적 서버를 하나 띄우고 브라우저로 엽니다.

```bash
cd exhibition/papa5
python3 -m http.server 8000
```

그다음 브라우저에서 **http://localhost:8000** 을 엽니다. (휴대폰 테스트는 같은 와이파이에서
`http://컴퓨터IP:8000`)

> 파일을 더블클릭(`file://`)하면 브라우저 보안 규칙 때문에 3D 모듈과 작품 목록(`works.json`)이
> 열리지 않습니다. 반드시 위처럼 서버로 열어 주세요.
> 그래도 안 되면 화면 아래에 이유가 표시됩니다.

## 2. 조작

| | 이동 | 시점 | 작품 선택 |
|---|---|---|---|
| **PC** | `W` `A` `S` `D` / 방향키, `Shift` 달리기 | 마우스 드래그 | 작품 앞에서 `E` 또는 작품/안내 버튼 클릭 |
| **모바일** | 왼쪽 아래 조이스틱 | 화면 드래그 | 화면 아래 「작품 보기」 버튼 |

- `Esc`: 정보 카드를 닫거나, 도움말(입장 화면)을 엽니다. `?` 버튼으로도 열 수 있습니다.
- 캐릭터는 이동 방향으로 돌아가고, 카메라는 뒤에서 부드럽게 따라오며 벽을 뚫지 않습니다.

## 4. 작품 추가하는 법 (코드 몰라도 됩니다)

지금은 작가 4명의 임시 작품 17점이 걸려 있습니다. 실제 작품 사진이 준비되면 **세 단계**면 됩니다.

### ① 사진을 `works/` 폴더에 넣는다

파일 이름을 **작품 id와 똑같이** 저장합니다. (영문 소문자+숫자 권장)

```
works/a01.jpg     ← id 가 a01 인 작품 사진
works/a02.webp    ← 확장자는 jpg·jpeg·png·webp 모두 됩니다
```

권장 규격: 긴 변 1600px, WebP 또는 JPG, 파일 하나에 200~350KB.
(원본 해상도 그대로 넣으면 휴대폰에서 메모리가 부족해질 수 있습니다.)

### ② `works.json` 을 열고 한 줄을 추가한다

지금 있는 줄 하나를 통째로 복사해 붙이고, 값만 바꾸면 됩니다.

```json
{ "id": "a06", "artist": "a", "title": "무제 #6", "year": "2027", "medium": "캔버스에 유채", "description": "", "image": "a06.jpg", "width": 1.4, "height": 1.8, "seed": 106 },
```

- `id` — 사진 파일 이름과 같게 (`a06` ↔ `works/a06.jpg`)
- `artist` — 어느 벽에 걸지. `a`=북쪽, `b`=동쪽, `c`=남쪽, `d`=서쪽
- `title`, `year`, `medium` — 제목·연도·재료 (정보 카드에 나옵니다)
- `description` — 작품 설명 (지금은 저장만 하고, 다음 단계 확대 화면에서 씁니다)
- `image` — 사진 파일 이름. `works/` 폴더 안의 이름이면 폴더 경로는 쓰지 않아도 됩니다.
  **비워 두면 사진 없이 임시 그림**이 걸립니다(없는 파일을 찾지 않으므로 오류도 없습니다).
  `"auto"` 라고 적으면 `works/` 에서 `id` 와 같은 이름의 사진(webp→jpg→jpeg→png)을 자동으로 찾습니다.
- `width`, `height` — 실제 크기(m). `1.4` = 140cm. **비워 두면 사진 비율로 자동 계산**합니다(높이 1.5m 기준)
- `seed` — 사진이 없을 때 그리는 임시 그림의 무늬 번호. 아무 숫자나.

### ③ 저장하고 브라우저를 새로고침한다

그 자리에 사진이 걸립니다. 사진이 없거나 파일이 깨져 있어도 **오류 없이 임시 이미지**가 걸립니다.
작품을 지우고 싶으면 그 줄을 통째로 지우면 되고, 개수가 늘거나 줄어도 벽에 자동으로 다시 고르게 배치됩니다.

### 자주 하는 실수

| 증상 | 원인 |
|---|---|
| 화면 아래에 "작품 목록(works.json)을 읽지 못했습니다 — N번째 줄…" | 그 줄의 쉼표·따옴표가 빠졌거나 남았습니다. (마지막 줄 뒤 쉼표는 괜찮습니다) |
| 작품이 안 보임 | `artist` 값이 `a~d` 가 아니거나, `{ }` 가 빠졌습니다. 콘솔에 어느 항목인지 나옵니다 |
| 사진이 안 걸리고 임시 이미지가 보임 | `image` 에 적은 파일 이름·확장자가 실제 파일과 다르거나(대소문자 포함), `works/` 가 아닌 곳에 있습니다. 개발자 도구 콘솔에 없는 파일 이름이 나옵니다 |
| 사진이 늘어나 보임 | 원본 비율과 `width`·`height` 비율이 다릅니다. 둘 다 지우면 사진 비율로 맞춰집니다 |

## 5. 그 밖에 자주 고치는 곳 (`js/config.js`)

### 전시 제목·기간·문구
```js
exhibition: {
  title: '파티프로덕션디자인 아카데미(PaPA) 제5회 마친보람맺음전',
  titleLine1: '파티프로덕션디자인 아카데미(PaPA)',   // 간판 윗줄
  titleLine2: '제5회 마친보람맺음전',                // 간판 아랫줄
  period: '2027. 01. 20 – 02. 28 (예정)',
  ...
}
```
> 정식 명칭은 `title`에 한 번만 정확히 적고, 간판은 두 줄로 나눠 그립니다. 띄어쓰기·괄호를
> 그대로 유지하세요.

### 작가 4명
```js
artists: [
  { id: 'a', name: '김동현', line: '한 줄 소개', palette: ['#d8c4a0', '#7c5f42', '#ece2cf'] },
  ...
]
```
`name`·`line`은 벽 위 작가 라벨에 그대로 나옵니다. `palette`는 사진이 없을 때 그리는 임시 이미지 색입니다.
작가 id(`a`~`d`)는 `works.json` 의 `artist` 값과 짝이므로 바꾸지 마세요.

### 공간·카메라·캐릭터
```js
space:  { hall: { width: 22, depth: 28, height: 4.6 }, ... , hangingHeight: 1.55 }
camera: { fov: 60, distance: 4.0, targetHeight: 1.52, pitch: 0.16, ... }
avatar: { mode: 'lowpoly', lowpoly: { height: 1.2, palette: {...} } }
theme:  { wall, floor, ceiling, frame, mat, bench, accent, fog ... }
```
- 관람객 캐릭터는 **로우폴리 인체 하나**입니다(키 1.2m, 머리가 조금 큰 약 4등신).
- 벤치 위치·안내판 위치는 `js/hall.js` 안에 있습니다(좌표 주석 참고).

### 관람객 캐릭터(로우폴리 인체)
- 캐릭터는 **로우폴리 인체 하나**입니다. 화면에 캐릭터를 고르는 버튼은 없습니다.
- 키는 `js/config.js` 의 `avatar.lowpoly.height`(기본 1.2m — 성인 실척이 아니라 관람객 캐릭터다운 작은 키),
  색은 `avatar.lowpoly.palette`(피부·옷·다리·신발·머리·눈)에서 바꿉니다.
- 몸 비례(머리·몸통·팔·다리 크기)는 `js/avatar.js` 의 `_buildLowpoly()` 안에 1.2m 기준 수치로 있고,
  `height` 에 맞춰 배율만 곱합니다. 머리 지름은 키의 약 1/4(약 4등신)입니다.
- 머리 위의 따뜻한 빛은 `avatar.glow`(lightColor·lightIntensity·lightDistance)에서 조정합니다.
- 이전 사람 실루엣(`human`)은 **롤백용으로만** 코드에 남아 있습니다 — 주소에 `?avatar=human` 을 붙이면 보입니다.
  (모르는 값이거나 `?avatar=prism` 처럼 없어진 값을 넣으면 기본 로우폴리로 열립니다.)

## 6. 지금 되는 것 / 안 되는 것

**되는 것**
- 3인칭 추적 카메라 + 관람객 캐릭터 — 로우폴리 인체(1.2m·약 4등신·파스텔 톤·점 눈 두 개),
  머리 위 따뜻한 빛, 걷기 애니메이션과 서 있을 때의 얕은 숨쉬기
- PC 키보드 이동·마우스 드래그 시점·Shift 달리기 / 모바일 조이스틱·드래그 시점
- 벽·벤치·안내판 충돌, 카메라 벽 관통 방지(막히면 앞으로 당김)
- 홀 하나(바닥·천장·벽 4면) + 입구 공간 + 입구 제목 벽(정식 명칭) + '입구/출구' 표지
- 벽 4면에 액자 17점(작품 목록은 `works.json` 에서 읽음) + 작가 구역 라벨 4개 + 홀 안 전시 안내판 + 벤치
- **사진만 `works/` 에 넣고 `works.json` 에 파일 이름만 적으면 그 액자에 걸림** — 없거나 깨진 사진은 임시 이미지로 대체, 오류 없음 (없는 파일은 요청하지도 않음)
- **작품 수가 늘거나 줄어도 벽 배치 자동** — 한 벽에 너무 많으면 간격을 좁히고, 그래도 넘치면 비율대로 줄여 벽을 벗어나지 않음
- 작품 앞 2.4m 안으로 들어오면 **액자 금색 하이라이트 + 작품 안내 버튼** 표시
- 작품 선택 시 **정보 카드**(작가·제목·연도·크기·재료) / 모바일은 「작품 보기」 버튼
- 로딩 진행률, 입장 화면, 첫 방문 안내, `?` 도움말, WebGL 미지원 2D 폴백
- 세로/가로 화면 대응(`100dvh`, 세로에서는 시야각·카메라 거리 자동 조정)

**아직 안 된 것(다음 단계)**
- 작품 **확대(큰 화면) 오버레이** — 지금은 정보 카드까지만. 카드의 "확대 감상 화면은 다음
  단계에서 연결됩니다" 문구 자리에 오버레이를 붙이면 됩니다. (`works.json` 의 `description` 은
  그 화면을 위해 이미 받아 둡니다)
- 실제 작품 사진·설명·작가 소개 문구(현재는 임시 이미지와 자리 표시자)
- 안내 투어, 작품 전체 목록, 배경음악, 방문자 통계
- 실제 폰(아이폰 사파리·안드로이드 크롬)에서의 발열·메모리 실측

## 7. 성능 메모

- 그림자 없음, 후처리 없음, 실시간 조명은 **환경광 1 + 스포트 3 + 캐릭터 상단 빛(포인트) 1** 개뿐입니다.
  (캐릭터 빛은 `avatar.glow`에서 세기를 0으로 두면 사라집니다)
- `devicePixelRatio` 상한 2, 세로 화면은 시야각을 조금 넓혀 같은 화면에 더 담습니다.
- 1초 평균 FPS가 32 미만으로 두 번 떨어지면 픽셀비를 자동으로 0.25씩 낮춥니다.
- 임시 이미지는 512px 캔버스로 만들어 메모리를 아낍니다. 실제 사진은 1600px·WebP를 쓰고,
  동시에 텍스처를 많이 올리지 않도록 주의해야 합니다(아이폰 사파리 텍스처 메모리).
- `?debug=1`을 주소에 붙이면 화면 왼쪽 아래에 FPS·좌표·근접 작품이 표시됩니다.

## 8. 검증 기록

### 2026-11-17 — 3단계: 추상 오브제 아바타 3종 (데-모 참고)

로컬 HTTP 서버로 이 폴더를 그대로 서비스하고 헤드리스 Chromium(Playwright, SwiftShader WebGL)으로 확인.

- 4가지 모드 모두 콘솔 오류 0건 · `__papaErrors` 0건 · HTTP 4xx 0건 · WebGL 정상(그리기 56~74회, 삼각형 604~2,494개)
- `?avatar=prism`·`cylinder`·`slab`·`human` 4개 주소 모두 해당 캐릭터로 열림, 파라미터가 없으면 `prism`
- 오른쪽 아래 버튼(프리즘/원기둥/판/사람)으로 즉시 전환 + 주소 갱신, 전환 뒤 드래그 시점 조작도 정상(camYaw 2.64 → 3.22)
- 오브제 자전은 이동 방향 회전과 별개: 정지 2초에 0.05 rad, 이동 중에도 +0.049 rad 계속 증가
- 이동: `D` 1.5초 → x 0 → 0.6m, 캐릭터 yaw 0 → −1.47 rad(이동 방향으로 회전)
- 모바일 390×844: 버튼 46~51×40px, 조이스틱·「작품 보기」와 겹치지 않음, 탭으로 전환 확인
- 기존 기능 회귀 없음: 작품 17점·근접 감지 17개, 사람 모드 걷기(다리 회전 0.48 rad)
- 스크린샷: `screenshots/avatar-prism.png` · `avatar-cylinder.png` · `avatar-slab.png` ·
  `avatar-human.png` (모바일: `avatar-mobile-slab.png`, `avatar-mobile-cylinder.png`)

### 2026-11-16 — 1단계 빈 전시장 데모

이 작업 환경에는 로컬 브라우저가 없어, **원격 헤드리스 브라우저에 이 폴더의 파일을 그대로
올려**(HTML·CSS·JS·vendor의 three.js 전부, import 경로만 blob URL로 치환) 실제 렌더링과
입력으로 확인했습니다. three.js는 이 폴더의 파일을 사용했습니다.
